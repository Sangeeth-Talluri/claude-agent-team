# Skill routing eval

A fixed set of sample tasks, each with the skill it must route to. Its job:
a skill edit, a router edit, or a prompt change that silently breaks routing
fails here, in the open, instead of degrading the bots in production.

The routes below come from the `using-our-skills` router in each control
plane. If a route in this file and a route in a router disagree, that is
itself a failure — fix whichever one is wrong and say which.

Added 2026-11-27, from the Addy Osmani Agent Skills adoption points
(`daily-scan/ADOPTION-BACKLOG.md`). Pairs with the cost-per-task eval rule
from 2026-11-26: this set judges *routing correctness*; that rule judges
*cost per solved task*. A change must pass both.

## How to run

This repo has no CI, so this eval is a **manual gate** — run it by hand,
every time, before committing a change to any file under either control
plane's `.claude/skills/` (including the routers themselves). If CI is
added to this repo later, this checklist becomes a required manual step in
the pipeline until routing can be checked automatically.

1. Start a fresh agent session in the control plane you changed.
2. Present each sample task for that plane, one at a time, exactly as
   written. Do not hint at the expected answer.
3. Record the first skill the agent routes to (the one it loads or names
   as the owner) next to the expected route.
4. **Pass rule:** every route matches. Any mismatch fails the change.
5. On a failure: fix the skill description or the router — whichever made
   the wrong route attractive — and re-run the *whole* set for that plane,
   not just the failed row. Do not edit this file's expected routes to
   match a wrong result; if you believe an expected route is itself wrong,
   that is a separate, deliberate change — say so in the commit message.
6. Log the run in the table below.
