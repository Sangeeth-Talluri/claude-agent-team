## Summary

- The day's big story is token thrift turning into a discipline with receipts. Caveman — "why use many token when few do trick" — sits at 123,234 stars, #1 on GitHub Trending and #1 on Hacker News, and its README now leads with outside-lab proof instead of its own claims: a JetBrains A/B on 86 real tasks found no measurable quality loss from terse agent output, Adobe Research's CAVEWOMAN paper measured 1.4–2.4× cheaper per model, and Elastic measured 63.6% fewer response tokens. The honest numbers are smaller than the headlines (8.5% fewer output tokens in the JetBrains test, not 33%), and that gap is the story: the win is real but it lives in what the agent reads and re-runs, not in how short its sentences are.
- Claude Code v2.1.332 (Nov 25) is the quieter release that matters more to this repo: MCP servers can now ship skills (`server:skill`, beta), and there is a new `PreSkillShellCommand` hook event that can refuse a skill's inline shell commands as it loads. Skills are now a supply chain, and Anthropic just shipped the checkpoint for it — two days after v2.1.331 made PreToolUse hooks fail open.
- Anthropic's August post on token economics ("Maximizing the value of your Claude Code sessions") is back in discussion this week, and the HN thread around it surfaced the two cheapest rules nobody had written down here yet: `/rewind` is free while `/compact` costs, and the prompt cache lives 1 hour on a subscription but 5 minutes on an API key.

## Top finds

### 1. Caveman v4.2.0 — terse agents with outside-lab proof, at 123k stars
- **Link:** https://github.com/JuliusBrussee/caveman
- **Attention:** 123,234 stars, 7,211 forks, created Apr 4, 2026, pushed today (2026-11-27), latest release v4.2.0. #1 on Hacker News and #1 on GitHub Trending; cited by Adobe Research, A/B tested by JetBrains, remade by Elasticsearch Labs. The attention signal is the outside validation, not the star count alone.
- **What it does:** Six parts in one install (`npx @caveman-ai/cli`): Say less (short agent answers, code stays exact), Read less (logs, JSON, CSV and test output shrink before the model reads them, originals kept on disk), Auto (a classifier picks model and effort per request), Blocks (code mode: the agent keeps the scripts it writes and re-runs them instead of rewriting them), Waste fixes (finds where tokens go, keeps the prompt cache warm while you pause), Browse (web pages come back compressed). Works with Claude Code, Codex, Gemini CLI, OpenCode and 30+ agents.
- **Real:** The README publishes its own limits, which is rare and worth trusting. The 33.2% fewer input tokens figure is 6 synthetic large-tool-output tasks, 18 pairs, on the August 2026 engine — and the README says so. The outside numbers are the real find: JetBrains ran 86 real coding tasks paired A/B and found no measurable quality loss (p = 0.82) with 8.5% fewer output tokens; Adobe's CAVEWOMAN paper (arXiv:2606.24083) measured 1.4–2.4× cheaper across eight models; Elastic measured 63.6% fewer response tokens with "zero information loss" across eight live MCP scenarios. Two findings shaped the design and both are portable: Adobe found cavemanning *your own* prompt makes answers worse, so Caveman never touches the user's prompt; JetBrains found agent sessions are mostly code and tool calls, which the voice leaves alone — so the savings come from shrinking what the agent reads and re-runs, not from short sentences. The Blocks number is concrete: one test run went from 397 tokens to 76 by re-running a kept script instead of rewriting it.
- **Hype/missing:** The Auto rock's headline — 0.46× the cost of Opus at xhigh — is an interim run on 85 tasks with the quality gap explicitly "unresolved" (±7 points). The Terminal-Bench 4 numbers at the top of the README (21% cheaper than Codex per solved task) are Caveman Code, the app, measured with three benchmark-only settings turned off in the shipped app — the README discloses this, but the headline doesn't. And the "33% fewer tokens" in the social posts is the input-token figure on synthetic tasks, not a whole-session saving; the JetBrains whole-session figure is 8.5%. The mechanism is sound; the marketing number is the synthetic one.
- **License:** Apache-2.0. **Maintenance:** Very active (pushed today, v4.2.0 current).
- **Verdict:** ADOPT — the pattern, not the install: terse agent voice, never rewrite the user's prompt, and keep-and-rerun scripts. This repo never installs third-party code; the rules go into the control planes as text.

### 2. Claude Code v2.1.332 — MCP servers can ship skills, and a new hook can refuse their shell commands
- **Link:** https://github.com/anthropics/claude-code/releases/tag/v2.1.332
- **Attention:** Official release, Nov 25, 2026 (latest). The release notes are the source; verified by reading them.
- **What it does:** Two changes matter here. First, skills from MCP servers (beta): they show as `server:skill` in the `/` menu, so a skill can now arrive from a connected server, not just from the repo or a plugin. Second, a new `PreSkillShellCommand` hook event that can refuse a skill or command's inline shell commands as it loads — on 2.1.331 and older, a settings file naming it just opens a dialog at start. Also in this release: a fix for CLAUDE.md and rules files being sent to the model a second time after a session moves into a worktree, and hook output over ~50,000 characters is now shortened instead of freezing the turn.
- **Real:** This lands two days after the Nov 24 finding that v2.1.331 made PreToolUse hooks fail open on error — the hook story is moving fast, and the Nov 24 hook-audit rule now has a second event to cover. The MCP-skills change is small in the notes but large in implication: the skill supply chain now includes every MCP server a bot connects to, which is exactly the surface the Nov 20 pre-flight security-scan skill was built to check. The worktree CLAUDE.md fix is a small token saving the repo gets for free on upgrade.
- **Hype/missing:** MCP skills are beta, and the notes say nothing about signing, provenance, or review for server-supplied skills — the checkpoint exists, the trust model doesn't. Most of the release is bug fixes (freezes, hangs, model fallbacks on Bedrock/Foundry); the two skill changes are the only new capability. Nothing here changes what the bots can do, only what they must be guarded against.
- **License:** N/A (Anthropic's own tool). **Maintenance:** Active (release Nov 25).
- **Verdict:** ADOPT — add a PreSkillShellCommand hook that refuses inline shell commands in skills, and treat MCP-server skills as untrusted until reviewed.

### 3. Anthropic's token-economics post, back in discussion — /rewind is free, /compact costs
- **Link:** https://claude.com/resources/articles/maximizing-the-value-of-your-claude-code-sessions
- **Attention:** Official Anthropic post by Lydia Hallie, published Aug 14, 2026; resurfaced in Hacker News discussion this week (HN TL;DR summary, and an ExplainX decode of the thread). The attention signal is the resurfacing and the thread's practical corrections, not a new launch — stated plainly because the post itself is three months old.
- **What it does:** Explains the billing mechanism, then derives six rules from it: `/clear` between tasks; set model and effort once at session start; @-mention files instead of naming them; quiet flags on noisy commands; `/compact` before a break while the cache is hot; offload large-output work to subagents. The mechanism: output tokens cost ~5× input because decode is sequential; cache reads cost 0.1×, cache writes up to 2×; the cache match must run from the very start of the request forward, so anything that changes the prefix busts it.
- **Real:** The two details worth adopting were not in this repo's Nov 25–26 cost points. First, `/rewind` is free — it only trims the end of the conversation — while `/compact` rewrites it, so nothing matches the cache afterward; prefer rewind to undo, compact only before a break. Second, the cache lives 1 hour on a subscription but 5 minutes on an API key (`ENABLE_PROMPT_CACHING_1H=1` raises the API case to an hour). The five cache-busters are explicit: `/model`, `/effort`, fast mode, `/compact`, and time. And the framing line is the one to keep: "Being efficient with tokens doesn't mean using fewer of them overall. It means making sure the ones you do use go towards the thing you actually asked for." The HN thread's pushback is also fair: commenters call it a product failure that the harness makes users manage this by hand, and note the advice is self-serving from a company that sells tokens — both true, neither a reason to ignore the mechanism.
- **Hype/missing:** The post is August; nothing in it is new except that people are arguing about it again. The `/compact` before a break tip assumes the cache is still hot — after an hour it isn't, and compacting then costs full price. `MAX_THINKING_TOKENS=0` for grunt work is in the post's tips and works except on Fable 5. No new tool, no numbers beyond the mechanism — this is a rules find, not a product find.
- **License:** N/A (blog post). **Maintenance:** N/A.
- **Verdict:** ADOPT — the /rewind-vs-/compact rule and the cache-expiry numbers, as session rules in both control planes.

### 4. Clawd HQ — a chief of staff for Claude Code, launched Nov 23
- **Link:** https://github.com/vedant-shah/clawd-hq
- **Attention:** 15 stars, created Nov 2026, updated Nov 23. The star count is weak; the attention signal is the launch coverage (Emergent, Nov 23) and that it is the first shipped implementation of the exact chief-of-staff pattern this repo designed on Nov 20. README verified by reading it.
- **What it does:** A Claude Code plugin (`claude plugin install clawd-hq@clawd-hq`, needs Claude Code v2.1.287+). You brief Clawd once; he picks specialists from your installed agents and skills, runs independent work in the background, and brings back one report while you keep talking. Delegates by default for anything more than one or two tool calls; each job gets the smallest model and effort that can do it; at most two skills per job, none for a one-file edit. A live pixel-art office panel shows the specialists at work.
- **Real:** Three rules in the README are directly usable, and none of them needs the plugin. First, specialists never stall mid-run for a question: they make their best call, finish the job, and list assumptions and questions at the end for Clawd — this is the missing half of the Nov 25 "needs you" queue, which only covers decisions a bot cannot make safely. Second, steer a running specialist with Claude Code's own agent messaging instead of restarting the job. Third, hiring discipline: a skill hired twice gets offered a permanent staff place; a generalist is the last resort; nothing is installed without your yes. The "right-sized hires" rule (smallest model and effort per job, max two skills) is the Nov 21 tiered-routing point with a concrete cap on skills attached.
- **Hype/missing:** 15 stars, four days old, one maintainer, and the pixel-art office is a gimmick — a live panel is nice, but the Nov 20 hook-timeline point already covers observability for this repo. The emergent.sh launch copy ("a shift from monolithic AI coding sessions to orchestrated specialist teams") is press-release language for a pattern Anthropic documented months ago. The README is honest that "free to talk is the aim, not a promise" — short direct jobs still make you wait. No evals, no cost numbers, no multi-user story.
- **License:** MIT. **Maintenance:** Brand new (updated Nov 23); watch whether it gets a second release.
- **Verdict:** WATCH the repo, ADOPT the three rules — they land in the Chief of Staff design, not as an install.

## Best of the best — adoption points

1. **Make bots say less, never rewrite the user's prompt, and reuse their scripts (from Caveman).** In `sre-agent-control-plane/`, `general-agent-control-plane/`, and `plans/claude-automate-anything-prompt.md`: bot-to-bot and bot-to-human text is short — code stays exact, prose is cut to the point (JetBrains A/B on 86 real tasks: no measurable quality loss, 8.5% fewer output tokens). Never rewrite the user's prompt to save tokens — Adobe found that makes answers worse, so Caveman never touches it; the user's words stay verbatim. And when a bot writes a script to run a check, it keeps the script and re-runs it instead of rewriting it each time (Caveman Blocks: one test run went from 397 tokens to 76). Extends the Nov 25 bundle-tool-calls point (write one script instead of many round-trips) with the keep-and-rerun half, and the Nov 26 rule-placement point: the terse-voice rule goes in the system prompt / `CLAUDE.md`, not only in a skill file. Source: https://github.com/JuliusBrussee/caveman
2. **Add a PreSkillShellCommand hook that refuses inline shell commands in skills, and treat MCP-server skills as untrusted until reviewed (from Claude Code v2.1.332).** In both control planes' `.claude/hooks/`: the new hook event fires as a skill loads and can refuse its inline shell commands — add it alongside the Nov 24 hook audit (which covers PreToolUse failing open on v2.1.331). And since MCP servers can now ship skills (`server:skill`, beta), a skill arriving from a server gets the same review as a skill from a repo before any bot uses it — the Nov 20 pre-flight security-scan skill's checklist gains one line: "list every skill source, including MCP servers." No skill, from any source, runs an inline shell command without a human-reviewed allow-list. Source: https://github.com/anthropics/claude-code/releases/tag/v2.1.332
3. **Specialists finish with assumptions listed — and steer them mid-run instead of restarting (from Clawd HQ).** In `bot-company/chief-of-staff/` and `plans/claude-persistent-bot-team-plan.md`: a specialist never stalls mid-run for a question — it makes its best call, finishes the job, and lists its assumptions and questions at the end. This reconciles with the Nov 25 "needs you" queue instead of replacing it: the queue is for decisions a bot cannot make safely; everything else finishes with assumptions listed. The Chief of Staff steers a running specialist with agent messaging when the brief changes, instead of killing and restarting the job. And the hiring rule: a skill hired for the same kind of job twice gets offered a permanent place on the team; a generalist is the last resort. Source: https://github.com/vedant-shah/clawd-hq
4. **Write the cache rules into the session rules (from Anthropic's token-economics post).** In both control planes and `bot-company/chief-of-staff/`: set model and effort once at session start — switching either mid-session busts the prompt cache and forces a full-price re-prefill. Prefer `/rewind` to undo (it only trims the end, so it is free) and use `/compact` only before a break while the cache is still hot (it rewrites the conversation, so nothing matches afterward). Remember the cache lives 1 hour on a subscription but 5 minutes on an API key. For grunt work, set `MAX_THINKING_TOKENS=0` for that session. These are the mechanism behind the Nov 25–26 cost points, now written as rules instead of advice. Source: https://claude.com/resources/articles/maximizing-the-value-of-your-claude-code-sessions
5. **Give the security-scan skill a disclosed-patterns file (from Claude-BugHunter).** In `sre-agent-control-plane/` and `general-agent-control-plane/`: extend the Nov 20 pre-flight security-scan skill with a patterns file — one short entry per vulnerability class, each drawn from a disclosed report (the BugHunter bundle curates 681 patterns across 24 classes). The scan checks the patterns file; the bundle itself is never installed. Verify the license before reusing any of its text (GitHub's license endpoint reports MIT, the repo view shows no license metadata). Source: https://github.com/elementalsouls/Claude-BugHunter
