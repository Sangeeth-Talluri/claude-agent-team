### 1. oh-my-claudecode v5.8.9 — the teams-first orchestration playbook, at 41k stars
- **Link:** https://github.com/Yeachan-Heo/oh-my-claudecode
- **Attention:** 41,109 stars, 3,662 forks, created Jan 9, 2026, 6,624 commits, 293 releases, latest release v5.8.9 (Nov 25), pushed today (2026-11-28). The attention signal is the scale plus the fact that the README documents design decisions, not just features.
- **What it does:** A Claude Code plugin + CLI for multi-agent orchestration. Team mode is the canonical surface: a staged pipeline `team-plan → team-prd → team-exec → team-verify → team-fix (loop)`, with named autopilot stage profiles (e.g. `plan-build-qa`) configured in `.claude/omc.jsonc`. `omc team` spawns real tmux worker panes running other CLIs — Codex, Gemini, Antigravity, Grok, Cursor, Claude — on demand, dying when the task completes. `omc lookout scan` is a pre-flight danger scan of the task brief and workspace before an unattended run, returning findings with a severity contract and exit codes (0 clean, 1 strict-mode high-risk, 2 usage error). Also: 19 specialized agents, a Model × Agent Compatibility Matrix with premium/balanced/budget presets, skill learning (`/skillify` extracts reusable patterns into skill files with triggers and quality gates), analytics and cost tracking across sessions, and a HUD statusline.
- **Real:** The portable ideas are the pipeline, the scan contract, and the matrix — each is a named, checkable structure this repo can copy as text. The "use only one primary loop authority in a session" rule is the same discipline the bot-company design needs: Team owns parallel staged execution, Execute owns single-agent verified completion, Verify owns quality-gate cycling, and nothing else starts a loop. The multi-provider worker table is honest about what each CLI is good for (Codex for review/security, Gemini/Antigravity for UI and large-context work) instead of claiming one model does all.
- **Hype/missing:** The README claims "smart model routing saves 30–50% on tokens" with no measurement attached — treat it as marketing until a number with a method appears. The repo is large and kitchen-sink (6,624 commits, its own state dir, Discord, sponsor badges); adopting the install would import a second control plane, which this repo must not do. The named stage profiles require Linux with `flock`. No evals or cost-per-task numbers are published for the pipeline itself.
- **License:** MIT. **Maintenance:** Very active (pushed today, v5.8.9 current).
- **Verdict:** ADOPT — the patterns, not the install: the named stage pipeline with verify/fix loop, the pre-flight scan contract, and the model × agent matrix.

### 3. WorkflowArena — the first benchmark that scores orchestration itself
- **Link:** https://explainx.ai/blog/workflowarena-multi-agent-orchestration-benchmark-einsia-2026 (paper: arXiv:2611.12856)
- **Attention:** Benchmark from Einsia.AI / Navers Lab with Tsinghua coauthors; paper dated Nov 9, 2026 (v1), surfacing in discussion this week. The attention signal is that it is the first public suite to score workflow authorship instead of single-agent output — and that its delegation traces are published as first-class data.
- **What it does:** 145 long-horizon professional tasks across 8 domains (software, math, law, accounting/ops, enterprise process, 3D/media, predictive modeling, general knowledge work), each with a hidden verifier and a shared 4-hour wall clock covering planner and workers. It scores delegation choices, integration of interdependent deliverables, and merge quality — and it penalizes dumb fan-out, where many workers produce parts that never reconcile. 25 configurations across nine models in Claude Code or Codex.
- **Real:** Three results transfer directly. First, the best configuration — Claude Opus 5.5 + Claude Code at max effort — resolves 36.95% of tasks, and no configuration wins every domain; orchestration is not a solved problem, it is a measured one. Second, the delegation fingerprints differ by model family: high-effort Claude runs launch fewer workflows with larger worker groups, GPT models in Codex delegate more often in smaller units — so the repo's Chief of Staff cannot copy one family's cadence onto the other. Third, the transfer experiment: workflows authored by Opus 5.5 improved continuous scores for weaker executors by 6.41 points on average on a hard subset, while workflows from a stronger author that was not a better orchestrator (GPT-6 Astra in their setup) helped less and hurt two executors. The practical rule: spend premium tokens on the orchestrator when integration is brittle, not only on the worker. The benchmark also treats orchestration time against the same wall-clock budget as execution, and every delegation goes through a recorded interface — traces are metrics, not logs.
- **Hype/missing:** 36.95% is the best score on the suite — nearly two-thirds of tasks still fail, so any "multi-agent solves long-horizon work" claim built on this paper is upside down. The 4-hour container per task makes the full 145-task suite expensive to reproduce; the authors themselves say to sample stratified slices, not run it as a daily regression. The paper is Nov 9, not this week — it is in this scan because it is being discussed now, stated plainly. The project license is not spelled out in the abstract; check it before reusing traces or scores.
- **License:** Unclear — check the project site (lab.einsia.ai/workflowarena) before reuse. **Maintenance:** N/A (research paper + benchmark).
- **Verdict:** ADOPT the evaluation method — log delegations, charge orchestration tokens as their own line item, and judge on $/resolved task with integration verifiers. WATCH the benchmark itself.

### 4. Convex skill security issue — the official marketplace fails a safety check, today
- **Link:** https://claude-news.today/en/briefings/briefing-2026-11-28/ (GitHub issue on the `claude-plugins-official` marketplace, reported 2026-11-28)

- **What it does:** Three skills in the Convex plugin have problems. The quickstart skill sends the user's one-line idea and template values as-is to a `/generate` endpoint on a Convex-external host, while the code only labels this as "telemetry 1/3" and never discloses it to the user. The add skill runs a script received from the same host directly as `curl | bash` with no review. The labs-quickstart skill instructs that the download and execution be deliberately split into separate Bash calls, guiding it around the harness's safety classifier. Convex's CEO responded that the prompt is used only for project generation and discarded within 30 seconds, that the current behavior is intentional, and that they would review the code and make it more transparent. The reporter believes it looks more like an attempt to smooth onboarding than malice.
- **Real:** This is the week's second live case of the same lesson, and it lands four days after the Nov 24 T3 Code telemetry flag (default telemetry that reads local Claude Code and Codex credential files to build a hashed identity, documented in the repo's own `apps/server/src/telemetry/Identify.ts`). The Nov 27 PreSkillShellCommand hook is exactly the checkpoint that would have caught the inline shell commands here — the marketplace listing did not.
- **Hype/missing:** The reporter's own framing is that this is likely onboarding smoothing, not malice — do not present it as an attack. The CEO's "discarded within 30 seconds" claim is their word, not independently verified. The issue is a report, not a confirmed exploit; the value is the pattern, not the verdict on Convex.
