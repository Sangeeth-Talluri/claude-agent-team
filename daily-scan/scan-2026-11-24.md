## Top finds

### 1. Claude Ship — Anthropic ships the PR pipeline: review, fix, approve
- **Link:** https://claude.com/resources/articles/introducing-claude-ship
- **Attention:** Announced Nov 23, 2026 by Anthropic (official blog, verified). For Claude Team and Enterprise plans on GitHub repos. Covered by multiple independent write-ups the same day.
- **What it does:** Three agents that take a pull request through review, fixes, and an approval decision. Code Review (already generally available) reviews a PR against the codebase through multiple lenses, verifies its own findings, and posts them. PR Steward (beta) keeps the PR green — it works on failing CI checks, merge conflicts, and review feedback, and after every push comments with what it changed and how to undo it; it is designed not to approve or merge. Claude Approvals (beta) reads a policy file (`.claude/approvals.yml`) in the repo and decides whether the PR is ready to merge — "a smarter CODEOWNERS file" — and can approve routine changes on its own if the policy allows. A `/ship` command in Claude Code pushes a change, opens the PR, and works the feedback loop. Admins pick a review level (Quick/Standard/Deep), set when reviews run, and cap spend; Anthropic recommends running approvals in observe-only mode first.
- **Real:** This is the missing half of the bot-company's merge step, shipped by the vendor: yesterday's scan added a diff-review-merge loop to the Chief of Staff, and PR Steward is exactly that loop with two disciplines this repo lacks — every fix push explains itself and how to undo it, and the fixer is structurally barred from approving. Anthropic's own numbers are concrete: on the Claude Code team, merged PRs more than doubled from June to September while the share reverted fell by more than 40%. The observe-mode-first advice is honest engineering, not marketing.
- **Hype/missing:** It is Team/Enterprise only, billed on tokens with no flat price, and not available with Zero Data Retention, HIPAA, or customer-managed keys — a personal bot team on a Pro/Max plan cannot turn it on at all. Anthropic's own docs warn plainly that "a pull request can merge when nobody but its author has looked at it" — the approval policy is only as good as the rules written in it. The June–September numbers are Anthropic's own team, not an independent measurement.
- **License:** Proprietary (Anthropic product). **Maintenance:** Active (announced yesterday).
- **Verdict:** ADOPT the pattern — a steward that fixes CI/conflicts and narrates each change with its undo, plus a written approvals checklist that decides merge, with a bot never approving its own work; do not adopt the product (plan-gated, token-billed).

### 2. Claude Code v2.1.331 — Code Mode spreads, and three hook defaults get looser
- **Link:** https://github.com/anthropics/claude-code/releases (changelog, as quoted by independent release trackers Nov 24)
- **Attention:** v2.1.331 published Nov 23, 2026; five releases shipped Nov 17–23 (2.1.327–2.1.331). Covered by three independent changelog trackers the same day.
- **What it does:** v2.1.331 adds Code Mode support in terminal sessions on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry, and Claude Platform on AWS, plus an API connectivity section in `claude doctor` and an MCP fix for tool calls that hung up to 30 minutes on malformed replies. The week's releases also extend `/loop` and recurring tasks from 7 to 30 days (2.1.330) and make `/tasks` a control panel for scheduled tasks and forks (2.1.329).
- **Real:** Two changes matter for this repo's control planes, which treat hooks as guardrails. First, in Code Mode a PreToolUse hook that errors no longer refuses the tool call — it fails open, where outside Code Mode it refused. Second, managed `PostToolUse` hooks no longer fire for calls refused before they ran, and Code Mode no longer runs UserPromptSubmit hooks on scripts' output — so a hook that was supposed to log or redact a refused call now sees nothing. Third, from a release on or after Nov 30, plugin marketplaces in managed `extraKnownMarketplaces` auto-update by default unless opted out.
- **Hype/missing:** None of these changes is labelled a security fix, and none is a vulnerability — they are default changes, and the release notes say so. But that is exactly the risk: a guardrail that silently stops firing looks identical to a guardrail that works. The 30-day `/loop` extension is genuinely useful for this repo's long-running bots, and the MCP hang fix is a real bug fix, not a feature.
- **License:** Proprietary (Anthropic product). **Maintenance:** Very active (five releases in a week).
- **Verdict:** ADOPT the audit rule — after every Claude Code upgrade, re-test every hook that must refuse, set `onFailure: block` on it, and pin marketplace auto-update off before Nov 30.

### 3. Graphify — your whole codebase as a queryable knowledge graph, no vector store
- **Link:** https://github.com/Graphify-Labs/graphify
- **Attention:** 152,789 stars, 14,686 forks, pushed Nov 23, 2026. Y Combinator S26; #2 fastest-growing open-source startup on the ROSS Index Q3 2026.
- **What it does:** A `/graphify` skill for Claude Code, Cursor, Codex, and Gemini CLI that maps a codebase — code, docs, SQL schemas, configs, PDFs — into a knowledge graph you query instead of grepping. Code is parsed locally with tree-sitter AST: deterministic, no LLM, nothing leaves the machine. Every edge is tagged `EXTRACTED` (explicit in the source) or `INFERRED` (resolved by graphify), so you can tell what was read directly from what was inferred. No embeddings, no vector store — a real graph you traverse, with a clickable `graph.html`.
- **Real:** The honest part is the split: the code map is free, local, and deterministic, which is exactly the kind of context a bot should get before it starts editing — a map of what connects to what, instead of re-reading the whole tree into context every session. The `EXTRACTED` vs `INFERRED` edge labels are a small, serious idea: they stop a bot treating a guess as a fact. Apache 2.0, very active.
- **Hype/missing:** The README's pitch is for the paid Graphify Cloud (always-on graph, cross-repo, Sentry/Jira connectors) — the free local skill is the demo for the cloud product, and docs/PDFs/images/video all need your assistant's model or an API key for a semantic pass, so "nothing leaves your machine" only covers code. A graph of a repo this size is a map, not understanding — a bot still has to read the files it changes.
- **License:** Apache-2.0. **Maintenance:** Very active (pushed Nov 23).
- **Verdict:** ADOPT (selectively) — lift the deterministic codebase-map step into the automate-anything prompt and the control planes; do not adopt the Cloud product.

### 4. CC Switch — one click switches provider, MCP, skills, and prompts across ten harnesses
- **Link:** https://github.com/farion1231/cc-switch
- **Attention:** 156,850 stars, 10,239 forks, pushed today (2026-11-24). v4.0.40 released Nov 23. Tauri desktop app for Windows/macOS/Linux.
- **What it does:** An all-in-one manager for Claude Code, Claude Desktop, Codex, Gemini CLI, Grok Build, OpenCode, OpenClaw, Pi, and more: switch API providers in one click and manage MCP servers, skills, and prompts in one place instead of hand-editing JSON/TOML/YAML config files.
- **Real:** The core idea is sound and maps directly onto this repo's Nov 21 tiered-routing point — today each bot's model tier lives in its own file, and switching a bot from one provider or model to another means editing that file. One switchboard that holds every bot's provider + model in one place is a real simplification, and it is also the vendor hedge: if Claude access changes, the same bots point at another provider. MIT licensed, released almost daily.
- **Hype/missing:** Read past the headline and the README is mostly paid advertising for API relay services — many promising Claude/Codex/GPT at 1–20% of official price, which is exactly the token-arbitrage business Anthropic's terms forbid for subscription use. A config switcher with ~157k stars is a strange number, and the relay-ad ecosystem around it is the likelier explanation than the switcher itself. The app edits the same config files a careful user could edit by hand; it adds convenience, not capability.
- **License:** MIT. **Maintenance:** Very active (pushed today, daily releases).
- **Verdict:** WATCH — borrow the one-place switchboard for provider + model per bot; do not adopt the app or any relay it advertises.

## Best of the best — adoption points

1. **Add a PR-steward + approvals-policy gate to the bot-company merge step (from Claude Ship).** In `bot-company/` and `plans/claude-persistent-bot-team-plan.md`: extend yesterday's diff-review-merge loop — when a bot's branch is ready, a steward step fixes failing checks and merge conflicts, and after every fix push it comments what changed and how to undo it; a written approvals checklist (the `.claude/approvals.yml` idea, as a plain checklist file) then decides whether the branch merges, and a bot never approves its own work. Run the checklist in observe mode first — log what it would have decided — before letting it gate merges. Source: https://claude.com/resources/articles/introducing-claude-ship
2. **Add a hook-audit rule after every Claude Code upgrade to both control planes (from Claude Code v2.1.331).** In `sre-agent-control-plane/.claude/hooks/` and `general-agent-control-plane/.claude/hooks/`: after any Claude Code upgrade, re-test every hook that must refuse a tool call, and set `onFailure: block` on it — v2.1.331 made Code Mode PreToolUse hooks fail open on error, and managed PostToolUse hooks no longer fire for refused calls, so a guardrail can silently stop firing. Also pin managed marketplace auto-update off before Nov 30, when it turns on by default. Source: https://github.com/anthropics/claude-code/releases
3. **Add a deterministic codebase-map step before a bot starts work (from Graphify).** In `plans/claude-automate-anything-prompt.md` and both control planes: before a bot edits anything, build a deterministic map of the files it will touch — what calls what, what depends on what — parsed from the code itself (AST, no LLM), and label every connection as read-from-source or inferred, so the bot never treats a guess as a fact. This replaces re-reading the whole tree into context every session. The local, free part of Graphify is the model; the Cloud product is not needed. Source: https://github.com/Graphify-Labs/graphify
4. **Add a central provider/model switchboard file to the Chief of Staff (from CC Switch).** In `bot-company/chief-of-staff/`: one config file listing every bot's provider and model tier in one place, switchable without editing each bot file — the Nov 21 tiered-routing point (Haiku/Sonnet/Opus per task size) made operable, and the vendor hedge made one edit instead of twenty. This is the switchboard idea only; no relay service and no third-party app. Source: https://github.com/farion1231/cc-switch
