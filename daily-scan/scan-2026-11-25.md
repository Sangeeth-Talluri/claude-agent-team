## Summary

- The day's theme is cost, measured honestly. Anthropic's experimental Code Mode (v2.1.323) lets Claude bundle tool calls into one script instead of round-tripping each step through the model — third-party tests show 22–77% fewer tokens, but the bill saving is smaller than the token saving, and one tester's first run cost 83% *more* because of cache-write pricing.

## Top finds

### 1. Headroom — a compression layer that squeezes agent context before the model sees it
- **Link:** https://github.com/headroomlabs-ai/headroom
- **Attention:** 80,835 stars, 6,342 forks, pushed today (2026-11-25). Trendshift #1 Repository of the Day badge on its README.
- **What it does:** Compresses everything an agent reads — tool outputs, logs, RAG chunks, files, conversation history — before it reaches the LLM. Ships as a library (`compress(messages)`), a proxy, an MCP server (`headroom_compress`, `headroom_retrieve`, `headroom_stats`), and a one-command wrapper for Claude Code, Codex, Cursor, Copilot, OpenCode, and more (`headroom wrap claude`). Compression runs on your machine; nothing is sent anywhere. Originals are cached locally and retrievable on demand. It also trims what the model writes back (output tokens), and `headroom learn` mines failed sessions and writes corrections into `CLAUDE.md`.
- **Real:** The measured claims are specific and modest where they should be: 21–57% fewer input tokens on four agent scenarios, 90%+ on repeated JSON arrays and log lines, "little on prose." That matches what compression can actually do — repetitive structured output compresses, prose does not. The reversible design (originals cached locally) is the honest part: a bot that needs the full log can still get it. Apache 2.0, created January 2026, very active.
- **Hype/missing:** The hero numbers (10,144 → 1,260 tokens on a log dump) are the easy case — repetitive logs. The README also advertises a paid "Headroom for Teams" tier and a cross-agent memory store, which are upsells around the core. The `learn` feature writes to your instruction files automatically, which is exactly the kind of silent self-editing that needs a human review step before it lands.
- **License:** Apache-2.0. **Maintenance:** Very active (pushed today).
- **Verdict:** ADOPT (the compression step) — a deterministic compress-before-context rule for tool outputs in both control planes; do not adopt `learn` writing to instruction files without a review gate.

### 2. Claude Code's Code Mode — bundle the tool calls, return only the answer
- **Link:** https://docs.byesu.com/en/articles/claude-code-code-mode-tokens (checked against Anthropic's docs, 2026-11-16); see also https://robotbelt.com/claude-code-mode-token-cost/
- **Attention:** Shipped in Claude Code v2.1.323 (Nov 17, 2026), experimental, off by default. Covered by at least four independent write-ups Nov 16–19 (Byesu, Robotbelt, Wavect, The AI Spotlight) plus a YouTube test; the numbers disagree with each other, which is itself the story.
- **What it does:** Instead of calling tools one at a time and reading every result, Claude writes one piece of JavaScript that makes the tool calls, filters the results, and returns only what matters. Enabled with `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1`. Anthropic's docs suggest it for tasks with many related tool calls — the same change across many files, a search whose results need filtering, several independent commands at once. The model-facing tool list shrinks from 16 definitions to three entry points.
- **Real:** The independent tests agree on direction and disagree on size, which is honest measurement: Bicameral ran 96 trials and found 62–77% fewer tokens processed on tool-heavy tasks, with all 16 runs correct in the heaviest case (120 tickets summed, context 54,000 → 3,500–8,800 tokens); bestagent.dev priced a CLI task falling from $0.45 to $0.35 (22% cheaper); one paired run on 40 order files showed 37% fewer input tokens. The mechanism is sound — the model stops paying to re-read tool definitions and raw intermediate results every turn.
- **Hype/missing:** Three corrections the coverage itself supplies. First, Anthropic's documentation makes *no* token-savings claim, and the "150,000 → 2,000 tokens (98.7%)" figure dates to a November 2025 research write-up, not to Code Mode. Second, tokens are not the bill: most session tokens are cache reads billed at 2.5–10% of base rate, so a 37% token cut can be almost nothing on the bill — and one tester's first Code Mode run cost 83% *more* at API prices because it wrote far more to the one-hour cache (writes cost 40x reads on Opus). Third, the failure mode is real: on Haiku, token use rose 9% in one test after a script picked the wrong directory and its error logs ate the saving, and three of Bicameral's failures all came from Haiku. It is also experimental, interactive-terminal only (not `claude -p`, SDK, VS Code, desktop, or cloud sessions), and does not start through a gateway, custom base URL, Bedrock, Google Cloud, or Foundry. And a script that edits many files in one step passes the per-tool-call hook checks only once, at the script level — which matters the day after yesterday's hook-audit point.
- **License:** Proprietary (Anthropic product). **Maintenance:** Active (shipped Nov 17; v2.1.331's hook changes, covered yesterday, interact with it).
- **Verdict:** ADOPT (with caution) — a bundle-related-tool-calls rule for the automate-anything prompt and both control planes, measured on cost not tokens, and never for destructive multi-file edits until the hook question is answered.

### 3. SoluTerminal — "Most of our Claude spend went on agents talking to each other"
- **Link:** https://soluterminal.com/guides/running-many-agents/
- **Attention:** Published Nov 19, 2026. A first-person post-mortem from a team running 10+ agent sessions at once (Claude Code and Codex side by side). No repo stars to quote — the attention signal is the measurement itself, which is unusually specific.
- **What it does:** The team asked its own agents to audit where the Claude spend went. For the week of Nov 1–8: 57% of spend went on turns started by another agent's message, with a median context of about 500,000 tokens; people started only about 20%. In eight days the agents sent each other about 7,800 messages, plus 1,457 more through a tool their own rules said not to use as a messenger. Some agents were simply repeating things to other agents.
- **Real:** The numbers are the find, and the two failures around them are the lesson. First, a structured workflow engine built to route each model to its strengths landed 0 of 69 tasks in October while 195 pull requests merged through direct agent sessions — they deleted it, about 532,000 lines, half of it tests, the day after the decision record said "delete later." Second, a slowdown they first blamed on hardware turned out to be ceremony: agents waiting on another agent for a "go," and a main branch frozen for about 37% of hours; merges fell from 33 a day to 12. The one fix that has shipped is agents taking shared machine capacity from a lock instead of asking another agent for it — the same lock idea this repo adopted Nov 23 from simlock, now with field evidence behind it.
- **Hype/missing:** It is one team's numbers on one stack (their own Windows app, SoluTerminal, Apache 2.0, 0 stars on GitHub — the product is not the story). The slowdown analysis admits the week also had a disk incident and a filming day, so the picture is not perfectly clean. And "too early to measure" is stated honestly about the lock fix. None of that weakens the central measurement: agent-to-agent chatter is where the tokens go, and nobody notices until they measure it.
- **License:** Apache-2.0 (the app). **Maintenance:** Active (pushed Nov 24).
- **Verdict:** ADOPT — a message budget and structured-report rule for the Chief of Staff, plus a weekly chatter audit.

### 4. The cost math of multi-agent orchestration — when delegation pays and when it adds 60%
- **Link:** https://claudefa.st/blog/guide/development/multi-agent-orchestration-cost
- **Attention:** Published Nov 10, 2026; surfaced in today's search for orchestration cost discussion. The find is the math, not the news — the date is stated plainly. Built on Anthropic's own published numbers and one Anthropic engineer's experiments (Lance Martin), with sources named.
- **What it does:** Answers one question: when does splitting work across models cost more than running one model straight through? On the full BrowseComp set (~31M tokens of reading per problem), a Claude Fable 5 orchestrator delegating to Sonnet 5 workers reached 96% of the score at 46% of the cost (86.8% accuracy at $18.53 vs 90.8% at $40.56 — Anthropic's numbers). On BrowseComp200, the easier subset (~0.37M tokens per problem), the same approach lost: Fable 5 alone was cheaper, and orchestration added a 60% markup for no benefit. Same models, same pattern — an 85x difference in reading volume flips the sign.
- **Real:** The mechanism is three costs, each with a fix. (1) Boundary cost: every token crossing between models is billed at least twice — brief out, brief read, report out, report read — about $0.14 of pure overhead per round trip at list rates, before the worker does anything useful. (2) Overlap: parallel workers that cannot talk to each other duplicate each other's reading; partition by source, not by question. (3) Cold cache: a fresh worker per request pays the cache-write price (1.25x) for context it has never seen; ten fresh workers means ten writes instead of one write plus nine reads at 0.1x. The article is honest about its own limits: Martin's results are one engineer's experiments, not official benchmarks, and Anthropic's advisor docs say results are task-dependent. It also notes the tension the numbers do not resolve — the value of a stronger model may sit in mid-task steering checkpoints, not in the upfront plan.
- **Hype/missing:** The $0.14 break-even arithmetic uses Sonnet 5 introductory pricing (through Aug 31, 2026); at standard rates the same handoff costs ~$0.156 and the 20,000-token case stops paying for itself entirely. And Anthropic documents that agent teams use approximately 7x more tokens than a standard session when teammates run in plan mode — the ceiling on what fan-out can cost. The table at the end is the usable part: delegate deep research and long refactors; run focused lookups and anything that fits in one context window straight through.
- **License:** N/A (blog post). **Maintenance:** N/A.
- **Verdict:** ADOPT — a delegation break-even rule for the Chief of Staff, with terse briefs and structured reports.

### 5. T3 Code — the open-source control plane for coding agents, from any device

### 6. Orca — a fleet of bots inside your agent IDE, asked from Slack or GitHub
- **Link:** https://github.com/stablyai/orca
- **Attention:** 137,380 stars, 8,793 forks, pushed today (2026-11-25). +1.5k stars today; trending again this week (+8.1k).
- **What it does:** Ask a bot in Slack, Linear, or GitHub to fix a bug and come back to a tested pull request. It runs on your own Claude Code or Codex, on your own machines. A coordinator agent runs worker agents in parallel workspaces; when a bot needs you, it shows a "Needs you" state with the question waiting. Desktop, mobile, and remote runtime; bring your own everything.
- **Real:** Two ideas land on this repo's design. First, the entry point: a bot can be asked from a chat message, not only assigned by the Chief of Staff — that matches how this user actually works (he asks in chat). Second, the "Needs you" state is the same blocked-bot pattern as T3 Code, implemented as a first-class status rather than a chat message that scrolls away.
- **Hype/missing:** "Fleet of bots" is a desktop app with a coordinator, not a managed service — the user still runs and watches the machines. The README's hero is a screenshot, not a measurement; there are no cost or success numbers. The bot-company design already has a coordinator and parallel workers; what Orca adds is the asking surface and the waiting state, not the orchestration.
- **License:** MIT. **Maintenance:** Very active (pushed today).
- **Verdict:** WATCH — borrow the "Needs you" state and the chat entry point (see adoption point 5); do not adopt the app while the bot-company is still a design, not a running system.

## Best of the best — adoption points

1. **Add a deterministic compress-before-context step for tool outputs to both control planes (from Headroom).** In `sre-agent-control-plane/` and `general-agent-control-plane/`: before a large tool result, log dump, or JSON blob enters the model's context, compress it deterministically (strip repeated lines, collapse repeated JSON arrays) and keep the original cached locally on disk, retrievable on demand — the Headroom shape, not the Nov 22 RLM handle shape (that one hands the bot a searchable pointer; this one shrinks the text itself). Add the same trimming to what the bot writes back when it pastes long outputs into reports. Measure on the repetitive cases (logs, JSON, test output), where Headroom measured 21–57% fewer input tokens and 90%+ on repeated structures; do not expect it on prose. Do not copy `headroom learn` writing corrections into instruction files without a human review step. Source: https://github.com/headroomlabs-ai/headroom
2. **Add a bundle-related-tool-calls rule to the automate-anything prompt (from Code Mode).** In `plans/claude-automate-anything-prompt.md` and both control planes: when a bot must run many related read/search/filter steps, it writes one small script that runs them and returns only the filtered result, instead of round-tripping each step through the model — the Code Mode pattern, usable today as a prompt rule even though the experimental feature is opt-in. Two guardrails with it: measure the saving on cost, not tokens (cache-write pricing can make the first run more expensive, and Anthropic's own docs claim no token saving); and never bundle destructive multi-file edits into one script until the hook question is answered, because a script passes the per-tool-call hook checks only once, at the script level — the day after the Nov 24 hook-audit point. Source: https://docs.byesu.com/en/articles/claude-code-code-mode-tokens
3. **Add a message budget and a weekly chatter audit to the Chief of Staff (from SoluTerminal).** In `bot-company/chief-of-staff/`: bots talk to each other only through short structured status reports — what changed, what is blocked, what is next — never free-form chat, and never through a tool the rules say is not a messenger. Once a week the Chief of Staff audits the message count and the spend share of agent-started turns, the way SoluTerminal found 57% of its spend on agent-to-agent turns with a median 500,000-token context and 7,800 messages in eight days. If a workflow or orchestration layer lands no tasks while direct sessions keep merging work, delete it instead of tuning it — their engine landed 0 of 69 tasks before they deleted 532,000 lines of it. Source: https://soluterminal.com/guides/running-many-agents/
4. **Add a delegation break-even rule to the Chief of Staff (from the orchestration cost math).** In `bot-company/chief-of-staff/` and `plans/claude-persistent-bot-team-plan.md`: the Chief of Staff delegates only when the worker will absorb enough reading to outweigh the fixed handoff cost — about $0.14 of pure overhead per round trip at list rates, every token billed at least twice (brief out, brief read, report out, report read). Three rules with it: briefs are terse and reports are structured (a 400-token findings note, never the full reasoning trace); work is partitioned by source, not by question, so parallel workers do not duplicate each other's reading; and repeat calls go to the same worker so its cache stays warm instead of paying a fresh cache write per request. Anything that fits comfortably in one context window, and any focused lookup with a known answer location, runs straight through with one model — on those, orchestration measured as a 60% markup for nothing. Source: https://claudefa.st/blog/guide/development/multi-agent-orchestration-cost
5. **Add a "needs you" queue for blocked bots (from T3 Code and Orca).** In `bot-company/`: when a bot hits a decision it cannot make safely, it stops and posts one short question with options to a single "needs you" queue — the T3 Code phone-approval and Orca "Needs you" pattern — instead of guessing, stalling silently, or asking in a chat message that scrolls away. No bot proceeds past a blocked decision, and the queue is the one place the user checks. This is the user-facing half of the Nov 24 approvals-policy gate (that one decides merges; this one surfaces blocked work). Source: https://github.com/pingdotgg/t3code and https://github.com/stablyai/orca
