## Top finds

### 1. ECC — the agent harness performance system
- **Link:** https://github.com/affaan-m/ECC
- **Attention:** ~307,579 stars, ~45,279 forks, pushed today (2026-11-20). Created Jan 2026. GitHub Trending regular.
- **What it does:** A Claude Code plugin (also Codex, Cursor, OpenCode and more) that installs a fixed engineering loop — plan → test → implement → review → verify → remember → improve — with 72 agents, 328 skills, hooks, memory, and an AgentShield security scanner.
- **Real:** The loop is genuinely the right shape, the memory/instincts idea (persist what matters, keep the context window small) is sound, and AgentShield (scan prompts, hooks, MCP config, permissions, secrets) fills a real gap. MIT licensed, single maintainer shipping weekly.
- **Hype/missing:** 328 skills is a bundle, not a system — most users will use a handful. The paid Pro tier (private repos from $19/seat/mo) sits on top of the free OSS. No independent evidence for its performance claims; stars measure popularity, not outcomes.
- **License:** MIT. **Maintenance:** Active (pushed today).
- **Verdict:** ADOPT (selectively — take the AgentShield scan and the memory/instincts pattern, not the 328-skill bundle).

### 2. Superpowers — agentic skills framework & dev methodology
- **Link:** https://github.com/obra/superpowers
- **Attention:** ~322,560 stars, ~28,655 forks, trending on GitHub today. In Anthropic's official Claude plugin marketplace.
- **What it does:** A set of composable skills plus starter instructions that force a workflow: tease out a real spec, show it in readable chunks, get sign-off, write an implementation plan "clear enough for an enthusiastic junior engineer," then run subagent-driven development with true red/green TDD.
- **Real:** The core insight is about the plan, not the code: if the plan is junior-readable and test-first, subagents stay on track for hours. That matches what this repo's automate-anything prompt already tries to do, but Superpowers states the bar more sharply.
- **Hype/missing:** It is a methodology, not a harness — there is no orchestration, no verification runtime, no guardrails beyond the skills themselves. "Works for a couple hours autonomously" is the author's claim, not a benchmark.
- **License:** MIT. **Maintenance:** Active (last push Nov 3, 2026; trending again today).
- **Verdict:** ADOPT — lift the spec-first + junior-readable plan + TDD gate into the automate-anything prompt.

### 3. Anthropic: Claude Code Projects gets a proactive coordinator + parallel workers
- **Link:** https://emergent.sh/news/claude-code-projects-adds-coordinator-btw (reporting Anthropic's @ClaudeDevs posts of Nov 13–14 and Anthropic docs at code.claude.com)
- **Attention:** Official Anthropic launch, covered by multiple independent outlets (AlphaSignal, dev.to, ai-oriens) in the last 5 days.
- **What it does:** A Project is now one long conversation with a coordinator that scopes work, delegates to parallel worker threads (each a full cloud Claude Code session on its own branch), answers questions and pushes status updates without being asked, and assembles results. New: `/btw` (side thread for tangents), `/fork` (branch an alternate implementation), read-only thread sharing links, scheduled thread reminders. Overlaps surface as ordinary Git merge conflicts.
- **Real:** This is Anthropic validating the exact Chief-of-Staff + worker-bot pattern in Plan 2 of this repo — coordinator, per-worker branches, merge-conflict surfacing. The proactive-status idea (coordinator reports instead of being polled) is the part worth copying first.
- **Hype/missing:** Public beta only, rolling out in stages to Pro/Max (waitlist; Team/Enterprise pending). Cloud-only for now; local execution "coming soon." New projects default workers to Opus at high effort, so parallel workers burn plan limits fast — a thread that hits a limit pauses and resumes. Not yet a local, self-hosted pattern.
- **Verdict:** ADOPT as the reference design — mirror its coordinator behavior in the bot-company Chief of Staff.

### 4. OpenSRE — the open-source agent for CI/CD reliability
- **Link:** https://github.com/Tracer-Cloud/opensre
- **Attention:** ~13,396 stars, ~1,917 forks, pushed today (2026-11-20), on GitHub Trending today.
- **What it does:** A CLI agent that reads a failed CI run, traces the cause, and pushes a fix for the human to review. Self-hosted, bring your own models.
- **Real:** Failed-run triage is the highest-value SRE bot job there is — it is bounded, verifiable (the fix either makes CI green or not), and keeps the human as reviewer. Directly maps to this repo's SRE control plane.
- **Hype/missing:** Public alpha — APIs and integrations may change, not yet stable. The "pushes a fix" step needs the same dangerous-command guard this repo already has; OpenSRE's own guard story is thin in the README.
- **License:** Apache-2.0. **Maintenance:** Active (pushed today).
- **Verdict:** ADOPT — add a failed-CI triage bot role to the SRE control plane.

### 5. Agent Flow — real-time visualization of Claude Code agent orchestration
- **Link:** https://github.com/patoles/agent-flow
- **Attention:** ~1,802 stars, ~221 forks, pushed Nov 18, 2026.
- **What it does:** Watches Claude Code (and Codex) sessions live and draws them as an interactive node graph — tool calls, branching, subagent coordination — plus a timeline, transcript, and file-attention heatmap. Runs as a VS Code extension or `npx agent-flow-app`. Built on Claude Code hooks.
- **Real:** This is the missing observability half of this repo's control planes: the hooks already exist (block-dangerous, require-evidence), but nobody can *see* what the agents did. A live event graph turns debugging from log-reading into looking.
- **Hype/missing:** Small project, single maintainer, 1.8k stars — no guarantee of long-term upkeep. Visualization only; it does not enforce anything.
- **License:** Apache-2.0. **Maintenance:** Active (pushed Nov 18).
- **Verdict:** ADOPT — add a hook-event live timeline to the SRE control plane.

### 6. oh-my-claudecode — teams-first multi-agent orchestration for Claude Code
- **Link:** https://github.com/Yeachan-Heo/oh-my-claudecode
- **Attention:** ~40,972 stars, ~3,655 forks, pushed today (2026-11-20).
- **What it does:** A Claude Code plugin that turns Claude Code into a multi-agent team setup with a single-command entry (`/autopilot "build a REST API..."`), team workflows, and an npm CLI path. Also ships a Codex sibling.
- **Real:** Large, actively maintained, and the "one command starts a team" framing is good UX. The teams-first framing is the closest public cousin to this repo's bot-company plan.
- **Hype/missing:** Heavyweight — it is a whole product to adopt, not a pattern to borrow. Adopting it would replace this repo's kits rather than improve them, and its scope keeps growing (the author now points heavy users at a lighter sibling).
- **License:** MIT. **Maintenance:** Very active.
- **Verdict:** WATCH — borrow the teams framing and the single-command entry; do not adopt the product.

### 7. CLI-Anything — making all software agent-native (HKUDS)
- **Link:** https://github.com/HKUDS/CLI-Anything
- **Attention:** ~61,047 stars, ~5,527 forks, pushed today (2026-11-20), on GitHub Trending today. From the HKUDS team behind DeepCode. Tech report arXiv:2606.03854.
- **What it does:** Generates CLIs that make any software usable by agents (Pi, OpenClaw, Claude Code, Cursor…), with a CLI-Hub registry to browse and install community-built CLIs, plus demos, preview loops, and 2,461 passing tests claimed.
- **Real:** The registry idea is genuinely useful — a shared shelf of tool CLIs beats every bot re-writing its own wrappers. The team is a serious research group with a track record.
- **Hype/missing:** Adjacent to this repo's lanes, not inside them: it is tooling *for* agents, not orchestration or a harness. "Making ALL software agent-native" overclaims — coverage depends on community CLIs actually existing for the tool you need.
- **License:** Apache-2.0. **Maintenance:** Active (pushed today).
- **Verdict:** WATCH — keep the CLI-Hub registry idea in mind for the bot-company platform layer; nothing to adopt today.

### 8. Plano — AI-native proxy server and data plane for agentic apps
- **Link:** https://github.com/katanemo/plano
- **Attention:** ~7,118 stars, ~498 forks. Last push Oct 24, 2026.
- **What it does:** An out-of-process data plane (built on Envoy) that centralizes agent routing, smart LLM routing (by model name, alias, or automatic preferences), guardrail filter chains, and OTEL traces/signals across agents — so each app stops re-building the same plumbing.
- **Real:** This is the token-optimization lane's only live idea today: route cheap sub-tasks to cheap models automatically instead of running everything on the flagship. The guardrail-filter and signal-capture ideas also map to this repo's control planes.
- **Hype/missing:** A proxy server is a big dependency for a personal bot team — it only pays off at multi-agent production scale. Hosted LLMs are free in US-central for first-run, production use needs local models or API keys. Not updated in the last month.
- **License:** Apache-2.0. **Maintenance:** Active but slower (last push Oct 24).
- **Verdict:** WATCH — note the model-routing idea for later; do not add a proxy server to a personal bot team now.

## Best of the best — adoption points

1. **Add a pre-flight security scan skill to both control planes (from ECC's AgentShield).** A new `.claude/skills/security-scan/SKILL.md` in `sre-agent-control-plane/` and `general-agent-control-plane/` that scans prompts, hooks, MCP config, permissions, and secrets before any bot runs — the same job ECC's AgentShield does. The dangerous-command hook already blocks bad actions at run time; this catches the bad setup *before* run time. Source: https://github.com/affaan-m/ECC
2. **Add a failed-CI triage bot to the SRE control plane (from OpenSRE).** A new agent file `sre-agent-control-plane/.claude/agents/ci-triage.md`: read the failed run, trace the cause, open a fix as a PR for human review — never auto-merge. The verdict gate is free: the fix either makes CI green or it does not. Source: https://github.com/Tracer-Cloud/opensre
3. **Add a live hook-event timeline to the SRE control plane (from Agent Flow).** The hooks in `sre-agent-control-plane/.claude/hooks/` (block-dangerous, require-evidence) already see every agent event; add a small viewer that streams those events into a live timeline/graph of tool calls and subagent branches, so debugging is looking instead of log-reading. Source: https://github.com/patoles/agent-flow
4. **Tighten the automate-anything prompt with Superpowers' bar (from Superpowers).** In `plans/claude-automate-anything-prompt.md`: require a written spec shown in readable chunks with human sign-off, an implementation plan "clear enough for an enthusiastic junior engineer with poor taste and no project context to follow," and true red/green TDD before any implementation step. Source: https://github.com/obra/superpowers
5. **Mirror Anthropic's coordinator pattern in the bot-company Chief of Staff (from Claude Code Projects).** In `bot-company/chief-of-staff/` and `plans/claude-persistent-bot-team-plan.md`: the Chief of Staff pushes status updates without being asked, each bot works on its own branch, overlaps surface as merge conflicts for human review, and a `/fork`-style rule lets a bot try an alternate implementation in parallel before the team picks one. Source: https://emergent.sh/news/claude-code-projects-adds-coordinator-btw (Anthropic @ClaudeDevs, Nov 13–14, 2026)
