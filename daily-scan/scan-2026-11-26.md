# Daily scan — 2026-11-26

**Date:** Thursday, November 26, 2026 (scan window: last ~24–48 hours)
**Theme:** Delegation has a price tag — and this week the numbers landed.

## Summary

- The week's big story is not a launch but a measurement: three independent pieces now price what delegation actually costs. A Japanese analysis of MCP subagents puts five parallel workers with full tool lists at $348.58 per 1,000 runs against $76.58 with scoped lists — a 78% cut from a config change, not a new tool. A 156-run test of Claude Code's Explore subagent finds it costs 2.7x as much, takes 3x as long, and leaves the main context the same size. And two harness evals agree the harness sets the bill while the model sets the score — pass rates sit inside rerun noise while cost per task moves up to 3x.
- Anthropic's own fix for the status-line token burn (v2.1.316, Nov 5–6) is still drawing discussion today: up to 16% of a session's token budget was going to a one-line status, and the fix — Haiku 5.5 writing it from short notes — is the same "cheap model for routine work" pattern this repo adopted Nov 21, now with vendor numbers behind it.
- Google's Agent Executor hit v0.4.0-rc.2 (Nov 25) the same week Google donated its Agent Substrate to the CNCF — the orchestration layer is commoditizing, which is good news for small teams that just need the patterns, not the platform.

## Top finds

### 1. The subagent MCP token tax, quantified — $348 vs $77 per 1,000 runs
- **Link:** https://nodeflare.tech/blog/mcp-subagent-token-usage
- **Attention:** Published Nov 21, 2026; surfaced in the Nov 22 Primary Source briefing and in today's searches. The attention signal is the math itself — a full worked calculation with tables, a break-even formula, and a checklist, cited by an independent briefing.
- **What it does:** Answers what five parallel subagents actually cost when each one inherits the full MCP tool list. Each subagent is its own model instance with its own context, so it pays the tool-definition tokens again — and because prompt cache only becomes available after the first response starts, five subagents launched at once each pay the full cache-write price ($2.50/MTok on Sonnet 5.5) instead of reads ($0.10/MTok). The worked example (5 subagents × 8 requests, 20,000-token tool list): all lists inherited + launched together = $348.58/1,000 runs; a cache breakpoint after the tools + staggering the first launch = $156.58; scoped 3,000-token lists per subagent = $76.58; the same 40 requests on one agent = $139.43. On Haiku, the scoped version costs $4.67. The break-even formula: delegation pays only when R × m ≥ P × (w/r + k − 1) — the tool results kept out of the main context, times the requests that follow, must exceed the prefix cost. For a 30,000-token result at k=8, that means the main conversation must run 24+ more requests with the full list, or 6+ with a scoped list.
- **Real:** The mechanism is documented from Anthropic's own docs (cache availability, subagent tool inheritance, agent teams at ~7x tokens in plan mode) and the arithmetic is shown in full, including the correction that MCP tool definitions are lazy-loaded by default in Claude Code, so the full-schema double-billing bites hardest on the Messages API and self-built orchestrators. The how-to section is concrete: `tools: Read, Grep, mcp__tracker__search_issues` per agent, `model: haiku` for simple workers, one-bot-only servers defined inline in `mcpServers`, `disallowedTools: mcp__*` to strip MCP entirely, `maxBudgetUsd` caps.
- **Hype/missing:** The author states plainly the numbers are calculations, not measurements ("以下の数値はすべて私の計算で、実測ではありません") — take the ratios as direction, not gospel. The last sections are a pitch for NodeFlare's own MCP hosting (scoped API keys, tool-search mode) — the analysis is the find, the product is an ad. And the lazy-loading caveat cuts both ways: in plain Claude Code the tax is smaller than the headline $348 suggests, because only tool names and server instructions load until a tool is used.
- **License:** N/A (blog post, Japanese). **Maintenance:** N/A.
- **Verdict:** ADOPT — scope every bot's tool list and add the break-even check to the delegation rule.

### 2. g-harness-evals — which harness solves tasks cheapest, measured not claimed
- **Link:** https://github.com/garrytan/g-harness-evals
- **Attention:** 177 stars, MIT, created Nov 5, 2026, updated today (2026-11-26). Small star count, but the attention signal is the method: Garry Tan's (Initialized Capital) open eval, cited in the Nov 9 Bam's AI Brief, with preregistered tests, published corrections, and full receipts. The README is the verification.
- **What it does:** Holds the model fixed (Claude Opus 5.5 or GPT-6.1 Sol) and the tasks fixed, swaps only the harness, and measures pass rate, cost per solved task, and time. On 20 multi-user tasks with Opus 5.5: QM (Pi loop) $0.19, Claude Code $0.22, Hermes Agent $0.24, OpenClaw $0.44 per solved task — pass rates 72.5–78.8%, no pair distinguishable. On 52 coding tasks: Pi $0.62, Claude Code $0.63, OpenClaw $0.88, Hermes $0.88. About 81% of OpenClaw's extra cost on Opus is cache writes, from a bigger system prompt and bigger tool results re-sent on every request.
- **Real:** The honesty is the find. Two findings matter more than the ranking. First, rule placement: a "check gbrain first" rule placed in the system prompt or a per-turn hook was followed in 30 of 30 turns; a skill nobody mentioned sat unread — Claude Code opened it 0 times in 30 turns. Second, workflow skills don't self-enforce: told to run gstack's /investigate, /qa, /review or /ship, Opus read the skill text every time and followed none of its steps (0 of 46 sessions), at about twice the cost per try. The README also publishes its own corrections (Nov 9–10), admits the OpenClaw "behind" call is fragile, and warns the tasks are public dev results, not hidden-task confirmation.
- **Hype/missing:** 177 stars and 52 coding tasks is a small sample — the 95% ranges are wide (Claude Code $0.41–$0.89 per solved task on coding). The multi-user tasks are a simulated company chat, not real production work. And the harness versions are pinned to early November; a patch release can move these numbers. The ranking is a snapshot, the rule-placement finding is the durable part.
- **License:** MIT. **Maintenance:** Active (updated today).
- **Verdict:** ADOPT (the rule-placement finding) — must-follow rules go in the prompt or a per-turn hook, and skills are named explicitly.

### 3. The Explore subagent test — 2.7x the cost, 3x the time, same context
- **Link:** https://aitoollabs.dev/posts/claude-code-explore-subagent-cost/
- **Attention:** Published ~Nov 16, 2026; surfaced in today's search for subagent cost discussion. The attention signal is the test design: 156 headless runs, four conditions, hand-graded against checklists written before the runs, full harness and grades published. The date is stated plainly — the find is the measurement, not the news.
- **What it does:** Asks whether Claude Code's Explore subagent saves tokens on "how does this code work" questions across three real repos (ky, requests, diff-tour) plus Django. Four conditions, 30 runs each: no subagent ($0.91), Claude decides ($1.03), forced Explore ($2.81), Explore pinned to Haiku ($1.13). Explore cost 2.7x, took a median 23s against 8s, and left the main context the same size (20,380 vs 17,973 tokens) — because the subagent's report takes about as much room as the excerpts Sonnet would have read itself. Left to decide, Claude never delegated to Explore once in 39 runs. The answers were slightly better with Explore (135/150 vs 130/150 checklist points), but the author would not pick it for quality on that margin.
- **Real:** Two corrections the test itself supplies. First, Explore runs on the main model, not Haiku as older guides say — that changed in 2.1.198, and moving it takes both `CLAUDE_CODE_SUBAGENT_MODEL=claude-haiku-5-5` *and* `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`; the first alone does nothing for built-in Explore/Plan. On Haiku the subagent read a median 92,033 input tokens yet all 30 runs together cost $0.16 — but took a median 32s, 4x the direct answer. Second, the Agent tool itself costs ~2,900 tokens on every main-model call, used or not — which is why no-subagent was cheapest even though default never called a subagent. The author also states what he did not measure: one question per session, so the long-session context-saving case is still untested.
- **Hype/missing:** One main model (Sonnet 5.5) and one version (2.1.325); with Opus as the main model Explore would run on Opus too, untested. Focused questions only — a task that makes the main agent read dozens of whole files would look different, and the author has not built that test yet. Grading was by one person, only partly blind.
- **License:** N/A (blog post). **Maintenance:** N/A.
- **Verdict:** ADOPT — pin subagents to Haiku, strip the Agent tool where it is not needed.

### 4. Anthropic fixes the status-line token burn — the cheap model does the routine work
- **Link:** https://www.mlllm.io/news/3739-anthropic-fixes-token-overconsumption-in-claude-code/ (sources: https://x.com/ClaudeDevs/status/2118063143167693011 and https://daily.dev/posts/claude-code-background-subagents-now-cost-about-99-less-per-status-update-ocseldjtf)
- **Attention:** Fix shipped Nov 5–6, 2026 in Claude Code v2.1.316; the daily.dev write-up carries 378 comments and was updated Nov 10; the mlllm item was updated today (2026-11-26). The attention signal is the discussion, not the launch — dates stated plainly.
- **What it does:** Background subagents were updating the status line every 30 seconds, and each update made the base model re-read the subagent's entire growing conversation. Now Haiku 5.5 writes the status line from short notes, without the full context. Up to 16% of an agent's token budget was going to a single-line status; the fix cuts cost per status update by about 99% and usage-limit consumption by about 5–6% in sessions with background subagents. One estimate in the coverage: a busy background agent making 120 status calls an hour cost about $4.80/hour even with all cache hits, before the fix.
- **Real:** The pattern is the find, and it is the same one this repo adopted Nov 21 (tiered routing): routine operational work goes to the cheap model. Anthropic applying it to its own product is the vendor confirming the pattern with numbers. The fix is CLI-only in v2.1.316, live for most Pro/Max/Ultra users and all Team/Enterprise.
- **Hype/missing:** The community take on daily.dev is 45% skeptical, 30% mixed — the honest read is that this was fixing a wasteful bug, not shipping a feature, and the "99%" figure is per status update, not per session; the real session-wide saving is about 5–6%. The 16% figure is an upper bound ("up to"), not a typical session. And the subagent's own model is unchanged — only the status line moved to Haiku.
- **License:** Proprietary (Anthropic product). **Maintenance:** Active.
- **Verdict:** ADOPT (the pattern) — offload routine operational work to the cheap model, in his own system.

### 5. "What Does a Harness Buy? Tokens, Mostly" — 8,032 trials, and the score gap is rerun noise
- **Link:** https://ajianaz.dev/coding-agent-harness-buys-tokens/ (study: "What Does a Harness Buy? Tokens, Mostly", arXiv, Yangze Liu and Zhongyi Han, Shandong University)
- **Attention:** Published Nov 3, 2026; discussed in the Nov 9 Bam's AI Brief and the Nov 22 Clouddo write-up, and surfaced again in today's searches. The find is the study, not the news — the date is stated plainly.
- **What it does:** Holds the model fixed and swaps the harness (Claude Code, mini-SWE-agent, OpenCode) across 8,032 trials on 492 SWE-bench Verified tasks. Rerunning identical configurations flips 13% of task outcomes at the median; swapping the harness flips 13%; swapping the model flips 22%. The harness sits on the rerun's noise floor. On the 447-task pool, Claude Code and mini-SWE-agent passed a 5-point equivalence test on both Qwen models. The bill is where the harnesses differ: cost per task up to 3x — one GLM-5.3-Flash trial cost 1.81 yuan under Claude Code, 0.97 under mini-SWE-agent, 0.56 under OpenCode — set at the first call (Claude Code's fixed cost: 17,134 input tokens vs mini-SWE-agent's 1,382) and scaled by steps (88.1 vs 80.2 vs 55.1 mean steps). Prompt caching does not rescue the heavy preamble: 96–99% of input tokens were cache hits in every arm, and the bigger preamble still cost more after the discount. One real harness effect cleared the noise, and it was a loss: OpenCode trailed by up to 9.2 points, half of it from runs its 32k output cap cut short.
- **Real:** The power analysis is the most reusable part: 45 tasks catch a 13-point gap only half the time; the 447-task pool resolves about 5 points. "When someone hands you a 2-point harness win, the right response is one word: rerun." The study also flags its own limits: one benchmark carries the main results, Claude Opus 5 ran only under Claude Code (80% on the hard set, far above open models at 24–58% — the model dominates where the harness does not), and the OpenCode time limit was not symmetric. The reproduce script rebuilds every table from the 8,032-row CSV on a laptop CPU in under a minute; code MIT, data CC BY 4.0. A side finding worth stealing for eval design: with web access on, 312 of 439 trials fetched the upstream fix from GitHub before attempting their own and passed at 96% vs 71% — the authors discarded every web-enabled result and enforced offline operation at the network layer, because "a prompt telling the model not to look things up is not a control."
- **Hype/missing:** The "small prompt does not guarantee a small bill" flip — on DeepSeek-V4-Flash the minimal harness took 141 steps against Claude Code's 104 and ended up the most expensive — means neither heavy nor light is always cheaper; the number to log is first-call input tokens plus steps per task, not preamble size alone. And the scaffolding does real work the score does not show: with thinking off, Qwen dropped 11.1 points in mini-SWE-agent but barely moved in Claude Code or OpenCode — tools, compaction, and long instructions buy something, just not measured pass rate.
- **License:** N/A (preprint + article). **Maintenance:** N/A.
- **Verdict:** ADOPT (the eval rule) — judge harness and skill changes on cost per task with a rerun, not on a single score.

### 6. Google's Agent Executor (AX) hits v0.4.0-rc.2 as its substrate goes to the CNCF
- **Link:** https://github.com/google/ax
- **Attention:** 14,903 stars, Apache-2.0, pushed today (2026-11-26). Release v0.4.0-rc.2 published Nov 25; Google donated Agent Substrate (which AX runs on) to the CNCF on Nov 20, with published sub-500ms recovery and 90–95% idle-state efficiency.
- **What it does:** An open agentic orchestration runtime on Kubernetes: a server, a controller, and runners that execute agent tasks as actors, with Postgres now holding actor state. This release moves the state store to Postgres, replaces UpdateTask with CreateTask (tasks are immutable — a change makes a new task), reverts crashed actors instead of recreating them, and handles transient substrate outages without permanently failing the task. The README describes AX as "running millions of tasks per cluster."
- **Real:** The CNCF donation is the bigger story than the release: the agent execution substrate is following the Kubernetes arc toward a provider-neutral commodity, and Perplexity's no-markup failover Orchestrator API (Nov 19) points the same way. For a small team the transferable idea is task immutability — a changed task is a new task, so the record of what was asked never gets rewritten.
- **Hype/missing:** This is cluster-scale infrastructure (Kubernetes, Postgres, actors) for running millions of tasks — not a tool for a bot team that is still a design, not a running system. "Millions of tasks per cluster" is a README claim, not a measured result in this release. The v0.4.0-rc.2 changelog is mostly fixes and API cleanup, no new capability his system lacks.
- **License:** Apache-2.0. **Maintenance:** Very active (pushed today).
- **Verdict:** WATCH — borrow the task-immutability pattern if the Chief of Staff ever keeps task records; do not adopt the platform.

## Best of the best — adoption points

1. **Scope every bot's tool list, and add the break-even check to the delegation rule (from NodeFlare).** In `bot-company/`: every bot's agent file gets an explicit `tools:` list naming only the MCP tools it needs (`mcp__server__tool` names, with the trailing `__*` on wildcards — `mcp__reports__v2` alone matches nothing), `model: haiku` for simple workers, and servers used by one bot only defined inline in that bot's `mcpServers` instead of shared `.mcp.json` — so a heavy server never enters the main conversation at all. Never let a bot inherit the full tool list by default. The analysis puts scoped lists at $76.58 vs $348.58 per 1,000 runs for five parallel workers, and $4.67 on Haiku. Add the break-even check to the Nov 25 delegation rule: delegate only when the tool results kept out of the main context, times the requests that follow, exceed the prefix cost (R × m ≥ P × (w/r + k − 1)) — a 30,000-token result needs 24+ following requests to pay for itself with a full list, 6+ with a scoped one. Short work stays in the main conversation. Source: https://nodeflare.tech/blog/mcp-subagent-token-usage
2. **Put must-follow rules where the model sees them every turn (from g-harness-evals).** In `sre-agent-control-plane/` and `general-agent-control-plane/`: any rule that must be followed goes in the system prompt / `CLAUDE.md` or a per-turn hook — never only in a skill file, because a skill nobody mentions can sit unread (their test: Claude Code opened an unmentioned skill 0 times in 30 turns, while a rule in the prompt or hook was followed 30/30). Name each skill the bot relies on in the prompt. And do not trust a workflow skill's steps to self-enforce: in their test Opus read gstack's skill text every time and followed none of its steps in 0 of 46 sessions — a skill's steps need a hook or a checklist that forces them, not just text. Source: https://github.com/garrytan/g-harness-evals
3. **Pin subagents to Haiku and strip the Agent tool where it is not needed (from the Explore test).** In both control planes and `bot-company/`: set `CLAUDE_CODE_SUBAGENT_MODEL=claude-haiku-5-5` *with* `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` — the first variable alone does not move the built-in Explore and Plan subagents, which otherwise run on the main model. Define custom subagents with `model: haiku`. In headless scripts that never delegate, pass `--disallowedTools Agent` — the Agent tool definition alone costs about 2,900 tokens on every main-model call, used or not. Evidence: Explore cost 2.7x as much and took 3x as long while leaving the main context the same size; pinning it to Haiku brought the cost back to roughly the direct-answer price. Source: https://aitoollabs.dev/posts/claude-code-explore-subagent-cost/
4. **Offload routine operational work to the cheap model (from Anthropic's status-line fix).** In `bot-company/chief-of-staff/` and both control planes: status lines, progress summaries, and any other text a bot writes about its own work run on Haiku from short notes, never on the main model with full context — the exact fix Anthropic shipped in Claude Code v2.1.316, where up to 16% of a session's token budget was going to a one-line status refreshed every 30 seconds. The honest number is ~5–6% session-wide, not the "99%" headline (that is per status update), and the community is right that this was fixing a wasteful bug — which is precisely why it belongs as a standing rule here, not a one-off fix. Extends the Nov 21 tiered-routing point to operational chatter specifically. Source: https://www.mlllm.io/news/3739-anthropic-fixes-token-overconsumption-in-claude-code/
5. **Judge harness and skill changes on cost per task, with a rerun (from the 8,032-trial study and g-harness-evals).** In both control planes' specs: when evaluating any harness, skill, or prompt change, measure cost per solved task — not pass rate alone, because pass rates sat inside rerun noise (harness swaps flipped 13% of outcomes, the same as rerunning the identical setup) — log first-call input tokens and steps per task, and rerun before believing any gap under ~5 points. The 447-task pool in the study resolves about 5 points; a 45-task comparison catches a 13-point gap only half the time. This is the eval discipline that makes the Nov 20–25 cost points measurable instead of vibes. Source: https://ajianaz.dev/coding-agent-harness-buys-tokens/ and https://github.com/garrytan/g-harness-evals
