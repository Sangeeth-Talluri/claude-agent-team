## Top finds

### 1. Parallel Code — ten agents, ten branches, one afternoon
- **Link:** https://github.com/johannesjo/parallel-code
- **Attention:** 1,105 stars, 152 forks, updated today (2026-11-23). Launched Nov 21, 2026 (covered in emergent.sh the same day). Repo created Feb 2026 — this is a launch, not a new repo.
- **What it does:** An Electron desktop app that runs coding agents from any vendor (Claude Code, Codex, OpenCode, Copilot, Antigravity) in their own git worktrees, one branch each. A board sorts tasks by what they need from you (Needs you / Stopped / Working / In PR); you review the diff, send line comments back to the agent, and merge or toss each branch. Per-agent cost tracking and token usage built in.
- **Real:** The worktree isolation is the cleanest answer yet to the parallel-bot collision problem — cheaper than containers, and git already knows how to merge the results. The review loop (diff → comment → agent fixes → merge) is the missing half of this repo's bot-company design, which today spawns bots and hopes merge conflicts sort it out. MIT licensed, real screenshots and a demo video, YAML manifests for agent config.
- **Hype/missing:** The launch article claims Windows support; the repo's own badge says macOS | Linux only — trust the repo. It is an Electron app with a big feature list (reasoning graphs, mind maps) that a personal bot team does not need; take the loop, not the app. 1,105 stars is modest — the launch is two days old, so treat this as early, not proven.
- **License:** MIT. **Maintenance:** Very active (pushed today).
- **Verdict:** ADOPT (selectively) — lift the worktree-isolated run + diff-review-merge loop into the bot-company; do not adopt the Electron app.

### 2. mobile-agent-testers — 20 AI testers on 20 phones, for $4.62
- **Link:** https://github.com/pierridotite/mobile-agent-testers
- **Attention:** 1,222 stars, 119 forks, launched on Product Hunt today (2026-11-23), pushed today.
- **What it does:** Each tester is a Claude Code agent with its own iOS Simulator or Android emulator on GitHub Actions, playing a persona (iPhone SE in Swedish at largest text size, Pixel 7 at 200%, iPad in German, Arabic right-to-left) and using your app like a new user — then writing a bug report with screenshots. No test scripts to write. Also does one-feature end-to-end runs, bug-reproduction across phones, improvement reports, and version-vs-version comparison. Runs on GitHub's free runners for public repos; you pay only for the model, about $0.15–$0.55 per phone.
- **Real:** The receipts are unusually good for a launch-day repo: a real 20-phone run on LocalSend found 46 distinct bugs (1 blocker) in 69 minutes for $4.62; AnkiDroid, 43 issues in under 10 minutes for $4.69. Every finding is documented with screenshots and the commands to re-run it. The cheaper-model note is honest — Haiku or DeepSeek work, but findings are only as good as the model's screenshot reading. MIT licensed.
- **Hype/missing:** This is mobile-app testing, and this repo's bots build back-end and SRE tooling — the pattern transfers, the tool does not. The "free runners" line only holds for public repos. A launch-day star spike is not the same as a maintained project; watch whether the author keeps publishing runs.
- **License:** MIT. **Maintenance:** Active (pushed today, launch day).
- **Verdict:** ADOPT the pattern — a parallel persona test swarm with version-compare reports belongs in the bot-company; the mobile tool itself is out of scope.

### 3. Claude Managed Agents, self-hosted — Anthropic's own control plane, inside your cloud
- **Link:** https://platform.claude.com/docs/en/managed-agents/overview (announcement covered at https://i10x.ai/news/anthropic-self-hosted-claude-managed-agents-private-beta)
- **Attention:** Anthropic announcement, Nov 12, 2026; private beta, access via an Anthropic account team. Covered by independent analysis (i10x) and the official docs.
- **What it does:** Managed Agents is Anthropic's hosted harness for long-running, stateful agents — agent loop, sandboxes, credentials, session history, multi-agent orchestration in beta. The self-hosted beta lets a team run the whole service in its own cloud or data center (server + PostgreSQL + one worker per session in its own sandbox container), while the model still runs on Anthropic's side. Multi-agent mode: a coordinator with a roster of up to 20 delegated agents, up to 25 concurrent threads, one level of delegation, threads sharing a filesystem but not context.
- **Real:** The design is the reference this repo's bot-company should measure itself against: per-session budget caps (the docs example caps a session at $1.25 and stops it mid-run), durable sessions that resume after pauses, event history you can fetch in full, and a hard limit of one delegation level — Anthropic itself does not let coordinators spawn coordinators. The self-hosted shape (Docker Compose quickstart) is the same shape this repo's control planes already use.
- **Hype/missing:** Private beta, no pricing, no general-availability date, and the model still leaves your network — this is self-hosted orchestration, not on-premises Claude. Not eligible for Zero Data Retention or HIPAA. Nothing here is adoptable as code; it is a design to copy and a product to watch.
- **License:** Proprietary (Anthropic product). **Maintenance:** Active beta.
- **Verdict:** WATCH the product, ADOPT the design — per-session budget caps and the one-level-delegation rule belong in the bot-company.

### 4. gentle-shell — a Pi-native workspace that treats the human as the lead
- **Link:** https://github.com/Gentleman-Programming/gentle-shell
- **Attention:** 2,900 stars, 301 forks, updated today (2026-11-23). Created May 2026.
- **What it does:** A terminal workspace for Pi (the open-source coding agent) that brings parallel coding agents, live tasks, git diffs, persistent memory, and permission controls into one shell — "your coding agent for controlled development in the workspace you lead." One prompt runs from idea to reviewed commit, with memory, workflow, and evidence kept together in the session.
- **Real:** The framing is the useful part: the human leads, the agent works, and every finished task closes with its evidence attached — memory note, workflow record, and diff in one place. Permission controls are first-class, not an afterthought, which matches this repo's dangerous-command guard. MIT licensed.
- **Hype/missing:** Built for Pi, not Claude Code — adopting it would mean switching runtimes, and this repo is Claude-first. The 2,900 stars are spread over six months, so the daily attention is modest. The demo video is the main documentation; the "controlled development" claim has no published measurement behind it.
- **License:** MIT. **Maintenance:** Active (pushed today).
- **Verdict:** WATCH — take the evidence-bundle habit (every finished bot task closes with memory + workflow + diff together), not the Pi runtime.

### 5. simlock — a lease desk so parallel agents stop fighting over the same device
- **Link:** https://github.com/callstackincubator/simlock
- **Attention:** 708 stars, 40 forks, updated today (2026-11-23). From Callstack (React Native specialists), created July 2026.
- **What it does:** A control plane for parallel coding agents that need real devices: an agent asks for an iOS simulator, Android emulator, or enrolled phone and gets one back, booted and checked, that no other agent touches until it is released. Creates devices when none is free, queues requests when the machine is full, cleans up devices nobody uses. One Mac to start; more machines behind a gateway when one is not enough.
- **Real:** This is the resource version of yesterday's file-lock point: locks stop two bots editing the same file, leases stop two bots grabbing the same simulator, port, or test account — same idea, wider scope, with queueing and auto-cleanup included. Small, honest scope: it does one job (device leasing) and documents it properly. MIT licensed, from a credible maintainer.
- **Hype/missing:** 708 stars is small, and it solves a mobile-testing problem this repo's bots do not have today — no bot here leases simulators. The gateway/fleet story is aspirational for a one-person team. Take the pattern, not the tool.
- **License:** MIT. **Maintenance:** Active (pushed today).
- **Verdict:** WATCH the tool, ADOPT the pattern — generalize yesterday's file locks into resource leases with queue + cleanup in the bot-company.

### 6. grok-build — SpaceXAI's coding-agent harness, now open source

- **Attention:** 27,837 stars, 5,261 forks, updated today (2026-11-23). Created July 2026.

Rust source, synced periodically from the SpaceXAI monorepo.

No adoption point survives that: the one transferable idea (ACP interop) is a standard, not a feature to lift.
- **License:** Apache 2.0. **Maintenance:** Very active (pushed today).
- **Verdict:** SKIP — a whole harness for a different model family; note ACP as the interop standard and move on.

## Best of the best — adoption points

1. **Add worktree-isolated parallel runs + a diff-review-merge loop to the bot-company (from Parallel Code).** In `bot-company/` and `plans/claude-persistent-bot-team-plan.md`: when the Chief of Staff runs parallel bots on one task, each bot gets its own git worktree and branch (the `/fork` pattern from Nov 20, made concrete); the Chief of Staff reviews each bot's diff, sends line comments back, and merges or tosses each branch — instead of letting bots edit the same tree and hoping merge conflicts sort it out. Per-bot cost tracking rides along, as it already does in Parallel Code. Source: https://github.com/johannesjo/parallel-code
2. **Add a parallel persona test swarm with version-compare reports to the bot-company (from mobile-agent-testers).** In `bot-company/`: a test pattern where N bots each take a persona (different device, language, font size, skill level) and use the finished work like a new user, then report with evidence; the same personas run against two versions and produce one comparison table of what changed. Cheaper models (Haiku) are fine for the swarm — this is the tiered-routing point from Nov 21 applied to testing. Source: https://github.com/pierridotite/mobile-agent-testers
3. **Add per-bot session budget caps with a hard stop to the Chief of Staff (from Claude Managed Agents).** In `bot-company/chief-of-staff/` and `plans/claude-persistent-bot-team-plan.md`: every bot session gets a dollar cap set before it starts; when the cap is hit, the session stops mid-run instead of finishing the request. Anthropic caps its own sessions this way (its docs example is $1.25); this repo's bots currently have no spending ceiling at all. Also adopt its one-level-delegation rule — a coordinator may spawn workers, workers may not spawn coordinators. Source: https://platform.claude.com/docs/en/managed-agents/overview
4. **Generalize file locks into resource leases with queue + auto-cleanup (from simlock).** In `bot-company/`: extends yesterday's file-lock point — a bot leases any shared resource (files, ports, test accounts, simulators) before using it; if none is free the bot queues instead of failing; idle leases are cleaned up automatically. One lease mechanism for every shared thing, instead of a separate rule per resource type. Source: https://github.com/callstackincubator/simlock
5. **Close every finished bot task with an evidence bundle (from gentle-shell).** In `bot-company/chief-of-staff/`: when a bot finishes a task, the Chief of Staff files one bundle — the memory note, the workflow record, and the diff — in a single place, before the next task starts. Today a finished task leaves its evidence scattered across chat, files, and memory; the bundle makes every completed task reviewable after the fact. Source: https://github.com/Gentleman-Programming/gentle-shell
