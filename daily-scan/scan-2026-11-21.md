## Top finds

### 1. TokenEconomizer — Microsoft's hook-based cost control for coding agents
- **Link:** https://github.com/microsoft/TokenEconomizer
- **Attention:** 7,879 stars, 544 forks, pushed Nov 20, 2026. Created Oct 13, 2026. Paper arXiv:2610.22732 (Microsoft Research + UC Berkeley). Covered by independent write-ups Nov 15–16.
- **What it does:** A Claude Code / Codex plugin that cuts agent cost without touching the agent or proxying requests. At session start a hook injects a few learned facts about the repo; after each tool call a loop guard watches for repeated failures and nudges; at session end it reads the agent's own log and updates what it knows. Unused tools go on a deny list so their definitions stop being sent on every turn.
- **Real:** The mechanism is sound and the measurement is public: 18.4–30.9% lower mean cost across five agent–model setups on SWE-Bench, cheaper in all 30 repo × combination cells, Pass@1 up in 4 of 5. It works with subscriptions (no API keys, no proxy), which is exactly how this repo's bots run.
- **Hype/missing:** The 18–31% is the paper's benchmark controller, not the plugin you install — the shipped plugin has learned facts off, prunes fewer tools, and only nudges, so the real saving is smaller. One independent analysis found it still drops two big tools Claude Code already defers, and resuming a session after tools change rewrites the whole cache. Trust its own cost ledger, not the headline.
- **License:** MIT. **Maintenance:** Active (pushed Nov 20).
- **Verdict:** ADOPT — the hook pattern (learned facts + unused-tool pruning + loop guard + cost ledger) ports directly into both control planes.

### 2. AX — Google's declarative orchestrator for agent workloads
- **Link:** https://github.com/google/ax
- **Attention:** 14,829 stars, 799 forks, pushed today (2026-11-21). Google org repo.
- **What it does:** Declare an agentic task in YAML (workspace + model spec), and AX sandboxes it, wires up the workspace, and runs it at scale on top of Agent Substrate. Kubernetes-style CLI: `ax apply`, `ax resume`, `ax describe`, `ax ssh` into a running task. Built to run millions of autonomous agent workloads per cluster.
- **Real:** The framing is right — agents are a new kind of workload (stateful, need isolation, can burn money in a loop), and the three primitives (sandbox, workspace, scale) are the correct ones. The `ax ssh` "look over the agent's shoulder" idea is genuinely useful.
- **Hype/missing:** The README itself warns it is in heavy development with major breaking changes likely before a stable release. Millions-of-tasks scale is a Google problem, not a personal bot-team problem; adopting AX would mean running a cluster to manage a handful of bots. No evidence yet of real-world usage outside Google.
- **License:** Apache-2.0. **Maintenance:** Active (pushed today).
- **Verdict:** WATCH — borrow the declarative task file + sandbox-per-task idea for the bot-company platform layer; do not adopt the runtime.

### 3. Deep Agents — LangChain's batteries-included agent harness
- **Link:** https://github.com/langchain-ai/deepagents
- **Attention:** 31,496 stars, 4,449 forks, pushed today (2026-11-21). LangChain org repo.
- **What it does:** An opinionated agent that runs out of the box on LangGraph: sub-agents with isolated context windows, pluggable filesystem, shell access, persistent memory, human-in-the-loop approval, skills, MCP tools — plus Deep Agents Code, a terminal coding agent like Claude Code that runs on any LLM.
- **Real:** The context-management features are the valuable part: it summarizes long threads and offloads tool outputs to disk instead of keeping everything in context, and memory persists across sessions. Model-agnostic (frontier, open-weight, or local) is a real hedge against single-vendor lock-in. Built on LangGraph, so streaming, checkpointing, and tracing come free.
- **Hype/missing:** "Production-ready" is LangChain's claim; it is still a framework you have to wire up, not a finished team. The coding-agent sibling is new and unproven against Claude Code itself. Adopting it would mean rebuilding this repo's kits on LangGraph rather than improving them.
- **License:** MIT. **Maintenance:** Very active.
- **Verdict:** ADOPT (selectively) — lift the context offload + summarization + persistent-memory pattern into the control planes; do not rebuild on LangGraph.

### 4. jcode — high-performance coding agents in Rust
- **Link:** https://github.com/1jehuang/jcode
- **Attention:** 21,965 stars, 2,568 forks, pushed today (2026-11-21). Y Combinator S26.
- **What it does:** A coding agent harness written in Rust, built for heavy multi-agent dev workflows: run dozens of agents in parallel "without melting your machine" — more agents, less RAM, no lag.
- **Real:** The performance angle is the one genuinely new claim in the harness race: if parallel agents each eat a full Node/Python runtime, a Rust harness that shares the cost is a real engineering advantage. YC backing and 22k stars in a young repo signal serious momentum.
- **Hype/missing:** The README leads with a performance demo video, not benchmarks — no published numbers for the RAM-per-agent claim yet. It is a whole harness to adopt, not a pattern to borrow, and it would replace this repo's Claude Code-based kits rather than improve them.
- **License:** MIT. **Maintenance:** Very active.
- **Verdict:** WATCH — if the parallel-agent RAM claim gets real numbers, revisit; the "dozens of agents, one lean runtime" idea is the right shape for a future bot-company platform.

### 6. Switch — AI teammates that live in your chat apps
- **Link:** https://github.com/sandbox-quantum/switch
- **Attention:** 4,681 stars, 367 forks, pushed today (2026-11-21). #1 Product of the Day on Product Hunt.
- **What it does:** Turns each Slack / Teams / Discord / Telegram / Mattermost channel into a "room" where people and AI teammates work together from shared context. Any agent, any model (Claude Code, Codex, Cursor, or your own) can join; self-hosted or Switch Cloud. Admins control who can talk to which agent and which connectors are on; guardrails and cost reporting included.
- **Real:** The "rooms" idea is the cleanest answer yet to where a bot team lives: the team already works in chat, so the agents join the chat instead of everyone learning a new tool. Per-room visibility (an agent only sees the rooms it belongs to) is a real safety boundary, and the admin-controlled connector list maps to this repo's guardrails.
- **Hype/missing:** License is Apache-2.0 **plus Commons Clause** — not pure open source; the clause restricts selling the software, which matters if the bot-company ever becomes a product. Switch Cloud is "coming soon," so today it is self-host only. 4.7k stars is modest next to the harness giants.
- **License:** Apache-2.0 + Commons Clause. **Maintenance:** Active (pushed today).
- **Verdict:** WATCH — borrow the room-scoped visibility rule for the bot-company; note the license caveat before adopting anything.

### 7. agent-model-router — the honest routing experiment (dev.to)
- **Link:** http://dev.to/kronx26/i-routed-claude-code-tasks-to-cheaper-models-heres-what-15-requests-saved-published-true-tags-53e7
- **Attention:** Published Nov 18, 2026 on DEV Community; an open-source skill (`npx agent-model-router install`), verified on Claude Code.
- **What it does:** A skill that asks one question before every task — how hard is this, really? — and sorts work into three tiers: Light → Haiku, Regular → Sonnet, Heavy → Opus. The main session sizes the task; a different tier goes to a helper agent locked to that model; if the helper fails, the task moves up one tier and never steps down. A tiny shared notes file (`.model-router/context.md`, ~40 lines) keeps helpers oriented without re-crawling the project. Every reply ends with a tag like `[router: light → haiku]`.
- **Real:** The test is small and the author says so: 15 requests, one project, 9% saved ($2.47 vs $2.70 all-Opus). The honest finding is the valuable part — Haiku never ran once, because briefing a helper costs more than the one-line edit it would do. The savings came from running regular work on Sonnet instead of Opus. "The cheapest model isn't always the cheapest option once you count the cost of getting work to it" is exactly right, and the escalate-only rule plus the "too small to bother" rule are the kind of guardrails that survive contact with real work.
- **Hype/missing:** One run, 15 requests, one small project — a hint, not a benchmark. Codex/Gemini/Copilot support is unverified (manual mode only). No GitHub star signal to judge adoption.
- **License:** Skill is open source (repo linked from the article; license not verified from the article page). **Maintenance:** Published Nov 18, install/uninstall verified by the author.
- **Verdict:** WATCH the numbers, ADOPT the rules — the three-tier routing + escalate-only + shared context file + model tag map directly onto the bot-company Chief of Staff.

### 8. Shark-Skills — run Claude Code like an engineering team
- **Link:** https://github.com/tusharsrivastava/shark-skills
- **Attention:** Only 14 stars — but launched on Hacker News and covered by independent press on Nov 17, 2026 (emergent.sh). Created Nov 16, pushed Nov 19.
- **What it does:** A Claude Code plugin that runs one operator session plus parallel "lanes" against a single shared contract. The main session never writes code: it briefs subagents, checks what they hand back, and talks to the user. Every merge gets audited, and every bug gets a root cause before it gets a fix.
- **Real:** The sharpest statement yet of the operator pattern — and the closest public cousin to this repo's Plan 2 (persistent bot team). "Every rule in here exists because breaking it cost me hours" is the right provenance for a rule set. The audited-merge + root-cause-before-fix discipline is exactly what a bot team needs before it is allowed near a real repo.
- **Hype/missing:** 14 stars and four days old — essentially unadopted, so there is no evidence beyond the author's own production story. It is one person's setup, not a tested system.
- **License:** MIT. **Maintenance:** New (pushed Nov 19).
- **Verdict:** WATCH the repo, ADOPT the rules — the operator-never-writes-code + audited-merge discipline belongs in the automate-anything prompt.
